## Implemented safety and operational changes

- Provider disconnect now rejects CREATED/PENDING/PROCESSING/AUTHORIZED/CONFIRMATION_PENDING
  payments for the immutable Venue/merchant identity. Reservation and disconnect lock the same
  merchant row. A previously selected inactive/stale connection cannot persist a new payment.
  Retry is idempotent. Historical payments preserve encrypted credentials; reconciliation selects
  historical merchant identity even when current Venue configuration changed. Device payment
  authorizations are disabled locally. Owner capability, recent PIN and audit remain in force.
  No ambiguous payment is classified terminal merely because disconnect was requested.
- Native secure session persistence now includes original session ID. Encrypted recovery envelopes
  preserve original actor/Venue/device/session; legacy/other-session records are blocked rather than
  adopted. Auth repository rejects session substitution; API checks the native provenance header
  and current revocation/expiry. Synchronous storage precedes commands. Malformed/unreadable
  collections fail closed without destructive replacement. Cash recovery prevents fresh-key repeats
  while unresolved evidence remains. Manager reconciliation and captured-intent device evidence
  still need completion; this is not a full recovery certification.
- Explicit `settings_production` refuses missing/weak secrets, wildcard hosts and non-HTTPS CSRF
  origins; enables SSL redirect/HSTS, secure cookies, CSRF/frame protection. Proxy trust is opt-in
  behind verified ingress stripping. Deploy check leaves W021 visible because preload is not
  authorized. [Executable deployment instructions](production-profile-round-2.md) distinguish
  local configuration from unverified TLS/proxy/rotation/monitoring/rollback/RTO/RPO.
- SSE poll reads release database connections; ASGI one-shot transport has an async iterator.
  Real replay/revocation evidence passed. Integration still emitted a synchronous-stream warning;
  intended-environment long-running resource capacity remains unverified.
- Guest service/bill requests persist as canonical DispatchTask with retry identity, occupancy/session
  authorization, exclusive ownership and audited completion. UI persists UUID before send and shows
  success only after server response. Guest payload never exposes staff identity. Typed management
  ages escalate the same original task; claim/acknowledgement never resets age or resolves work.
- Native AGORA no longer labels closed historical tabs as open accounts. CONTAS retains history;
  outstanding delivery tasks remain independent from financial close.
